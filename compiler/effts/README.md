# effts — Python port of `efficient-trotterizations`

A Python port of the evaluation and application layers of
[MarkoMalezic/efficient-trotterizations](https://github.com/MarkoMalezic/efficient-trotterizations)
(commit `1a5a168`, MIT, see `data/LICENSE-upstream`). That repository
accompanies M. Maležič and J. Ostmeyer, *Efficient Trotter-Suzuki Schemes for
Long-time Quantum Dynamics*, [arXiv:2601.18756](https://arxiv.org/abs/2601.18756)
(v3). Equation, table and figure numbers below refer to v3.

The port exists so that the paper's schemes can later be compared fairly
against simcount's product formulas.

## What is and is not ported

| Upstream | Here | Notes |
|---|---|---|
| Scheme data, `Recommended_schemes/*.out` | `data/recommended/` (copied), `schemes.py` | All 63 schemes, orders 2–8, q ≤ 30 |
| File / stage / ramp notations (`Trotter::to_standard`, `to_ramp`, Eq. 9) | `schemes.py` | |
| Err_n, Eff_n, x̄ (Eqs. 20, 22, 23) | `bch.py`, `schemes.py` | **Recomputed independently**, not transcribed: see below |
| Commutator basis (`Recursive_formulae.tex`) | `basis.py` | Generated by regex from the `.tex` |
| Heisenberg chain (`Model.cpp`) | `heisenberg.py`, `paulis.py` | XXZ, XZ, general; periodic or open |
| Trotter step, both groupings (`Trotter.cpp`) | `evolution.py` | Operator method, real time |
| Exact evolution and Δ_exp (Eq. 25) | `evolution.py` | |
| LM minimiser, symbolic mode (~16k lines C++) | **not ported** | Its output, the scheme data, is what is used |
| Recursive formulae (`NCoefficients.cpp`) | **not ported** | Replaced by the independent BCH computation |
| Harmonic oscillator (`Symplectic_evolution.py`) | **not ported** | Not needed for spin-chain / simcount work |
| State method, imaginary time, complex schemes | **not ported** | Not used by any figure checked here |

How Err_n is computed. Upstream evaluates hand-derived recursions (Sec. 2.2).
`bch.py` instead multiplies out the scheme's exponentials in the free algebra
on {A, B}, truncated at degree 9, takes the logarithm, and projects each
degree onto upstream's basis. The two codes share only the definition of the
basis. Because they agree, both the recursion and the published coefficients
are confirmed.

## Running

From `compiler/`, in the `pennylane` env. No new dependencies; NumPy and
SciPy only.

```
python -m pytest effts/tests -q        # 341 tests, ~20 s, no Docker
python -m effts errors                 # Err_n of all published schemes vs upstream
python -m effts table4                 # paper Table 4
python -m effts fig5                   # paper Fig. 5, both groupings
python -m effts fig6 --L-max 12        # paper Fig. 6 (L=11: ~4 min, L=12: ~21 min)
python -m effts ranking                # the "q=14 best at each cost" claim
```

Nothing is random. The magnetic fields are upstream's own `hmag = random`
values (mt19937 with seed 42, U[−0.1, 0.1]), recorded in
`fixtures/upstream_fields.json`.

## Evidence

| Claim checked | Against | Result |
|---|---|---|
| Symmetric-BCH coefficients α̃ … ε̃₅₆ (82 values) | `Recursive_formulae.tex` | exact to 1e-17 |
| Err_n² for every published scheme, n ≥ order (110 values) | upstream `.out` files | ≤ 7e-8 relative (double vs quad arithmetic) |
| Order conditions of every published scheme | ν = σ = 1, Err_k = 0 for k < n | ≤ 1e-13 |
| Each scheme's order, from step-size scaling | random matrices, no BCH code | slope n + 1 ± 0.25 |
| Leading error *operator* h^{n+1} O_{n+1} | `logm` of the actual matrix product | converges like h² |
| Table 4 (Eff_n, x̄ for 6 schemes) | paper | every printed digit |
| Δ after every step, 20 cases (635 values): both groupings, XXZ / XZ / general, open / periodic, L = 2–6, 8 schemes | **upstream C++ binary**, built unmodified | ≤ 5e-14 absolute |
| Fig. 5, every point of 6 curves × 2 groupings (~610 points) | paper SVG, digitised | ≤ 4e-4 decades (= SVG resolution) |
| Fig. 6, L = 2–12 | paper SVG, digitised | ≤ 1e-4 decades (see `python -m effts fig6`) |
| How N_t is rounded in Fig. 6 (not stated in the paper) | paper SVG | `round(500/q)` fits; floor and ceil miss by 30–500× the precision |

The upstream binary was built in a throwaway container (`ubuntu:22.04`, g++
11.4, Eigen 3.4.0, HDF5 from apt) and run with scalar type `double`. To
regenerate its fixtures:

```
docker run -d --name effts-ref ubuntu:22.04 sleep infinity
docker exec effts-ref bash -c 'apt-get update && apt-get install -y g++ cmake libeigen3-dev libhdf5-dev'
docker cp <upstream>/Code/Time_Evolution effts-ref:/src/Time_Evolution
docker exec effts-ref bash -c 'cd /src/Time_Evolution && mkdir build && cd build && cmake -DCMAKE_BUILD_TYPE=Release .. && cmake --build .'
python -m effts.reference
```

To regenerate the digitised figures:
`curl -sL https://arxiv.org/html/2601.18756v3 -o paper.html && python -m effts.digitise paper.html`.

## Disagreements found (reported, not adjusted)

1. **Table 3 ≠ repository.** The q = 14 order-6 scheme printed in Table 3
   differs from the repo's version by up to 1.5e-6 in the stage weights. The
   q = 6 scheme of Table 2 differs by about 1e-10. Both printed tables are
   valid schemes of their order (residues ~1e-17) with the same Eff to 4
   digits. At q = 14, order-6 schemes have free parameters (Table 1), so
   these are two nearby points on the same family. The port uses the repo
   versions, which are the ones Fig. 5 was computed with: the Fig. 5 match
   to 4e-4 decades depends on it.
2. **Seven stale distances upstream.** For seven order-8 schemes the "Distance
   from the origin" printed in `Recommended_schemes` does not match the
   scheme's own coefficients. For q = 22, 24 and 28 it is exactly the
   distance of an earlier archive version of the scheme. For q = 17 it is
   unexplained. None of these schemes is used in the paper's tables or
   figures. They are listed in `tests/test_effts_schemes.py`.
3. **"Better at each cost" holds only above cost ≈ 120–140.** Sec. 3.1 says
   the q = 14 scheme beats the historical schemes "at each cost … even at
   lower costs where the Leapfrog scheme was thought to excel". In the
   paper's own Fig. 5 data, Leapfrog beats it below cost ≈ 90 (global) and
   ≈ 105 (local), and the paper's q = 6 scheme beats it below ≈ 120 and
   ≈ 133. In that range Δ ≈ 0.1–0.5. Above it, q = 14 is best in every case
   checked.
4. **Paper Sec. 2.3** calls the origin "c_i = d_i = 1/q". Eq. (23), Σ c_i = 1/2,
   and the upstream x values all require 1/(2q).
5. **Upstream comments invert `group`.** `Trotter.h` and `InOut.cpp` say
   "local = 0, global = 1", but `group = true` runs the local branch. The
   port follows the code.

## Not reproduced

- **Morales et al. schemes (q = 17, order 8; q = 33, order 10) in Figs. 5–6.**
  Their coefficients are not in the upstream repo, and I have not transcribed
  them from Morales et al. (2022).
- **Blanes & Moan coefficients.** These are taken from upstream's input files.
  They have **not** been checked against Blanes & Moan (2002).
- **Fig. 4 (experimental efficiency).** It needs a rescaling constant Ω₀ that
  the paper tunes by hand and does not report.
- **Figs. 3, 7–11.** Theoretical efficiency is covered by the Err_n checks;
  the harmonic oscillator and Sec. 4 are out of scope.
